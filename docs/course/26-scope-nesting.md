# 26 · 谁真的缩小了范围

> 一句话模型：嵌套只改书写方式，编译后仍是扁平选择器；`@scope` 才是给样式一个 DOM 子树边界并加邻近性排序；`:has()` 只把匹配方向反过来。三者都不改 DOM，也都不免掉第 03 篇的层叠关卡。

## 先看一个现象

```css
.card {
  & button { color: red; }
}
@scope (.card) {
  button { color: blue; }
}
.card:has(button:disabled) { opacity: 0.6; }
```

你以为三行都在做"让样式只作用于这个组件"：第一行把规则收进 `.card`，第二行把范围锁进子树，第三行根据内部状态选中卡片。实际：`& button` 编译成 `.card button`，嵌进来的第三方按钮一起变红；`@scope` 只限制"哪些元素参与匹配"，卡片里继承来的 `font-family` 照样穿过边界；`:has()` 连 DOM 都没碰，只是让 `.card` 因为后代的状态被选中了。

三个"局部感"来自三个完全不同的轴：**书写组织、影响范围、匹配方向**。混着用，就会以为拿到了样式隔离——其实谁也没给。

## 先建立直觉

![`:has()` 把匹配的箭头掉了个头](figures/26-scope-nesting.svg)

*图 26-1 · `:has()` 把匹配的箭头掉了个头*

图上是同一棵小 DOM 树画了两遍。左半：普通选择器 `.card button` 的箭头从外向内、从父到子，先圈出 `button` 再往祖先验证。右半：`.card:has(button:disabled)` 的匹配箭头从内部的 `button:disabled` 出发，反向指回外层的 `.card`；DOM 树的节点、连线、顺序一模一样，只有箭头方向反了。读者应当看出：变的是"谁被选中"，不是"树长什么样"。

图里最关键的一条：**`:has()` 是条件反向，不是结构变化**。它让父子关系反过来当筛选条件，所以写它的代价是可审查性——表达式越复杂，越难一眼看出选中了谁。

## 机制拆成四步

### 1. 原生嵌套：语法糖，不是作用域

`&` 指向外层选择器本身，可以放在链首、链尾或中间：

```css
.card {
  &:hover { border-color: #3157d5; }      /* .card:hover */
  & .title { font-weight: 700; }          /* .card .title */
  .theme-dark & { background: #171a21; }  /* .theme-dark .card */
}
```

不写 `&` 的子规则会自动补成后代选择器：

```css
.card {
  & > h2 { margin-block: 0; }    /* .card > h2 */
  a { color: #2548bd; }          /* .card a */
}
```

**为什么它不算作用域？** 因为浏览器最终存的还是扁平选择器，和手写的 `.card button` 没有区别；第 03 篇那串关卡——来源、重要性、层、优先级、作用域距离、书写顺序——一条都没少。嵌套后的优先级类似 `:is()`：取参数里最高的一项，不会因为套了三层就自动"组件隔离"。`.card { & .title {} }` 与 `.card .title` 的优先级完全相同，前者只是把后者写在了一个更近的位置。

### 2. `@scope`：限定参与匹配的子树，再加邻近性

```css
@scope (.article) to (figure) {
  img { border: 2px solid #16805a; }
}
```

根（`.article`）包含在内，下限（`figure`）及其子树被排除，形成一个"甜甜圈"。同一个 scope 里的写法是这样的：

```css
@scope (.theme) {
  :scope { padding: 1rem; }     /* 指 .theme 本身，带类级优先级 */
  & a { color: #2548bd; }       /* .theme a */
  p { line-height: 1.6; }       /* 裸选择器 ≈ :where(:scope) p */
}
```

`:scope` 指根本身；不带 `&` 的裸选择器相当于前面隐式加了零优先级的 `:where(:scope)`。**为什么这个区别重要？** 显式写 `:scope` 会引入一个类级优先级位，而裸选择器不增加优先级——想让后续普通类能轻松覆盖，就用裸选择器；要锁定根节点本身，才写 `:scope`。比起堆叠类名，scope 把"这段样式只管这棵子树"写成一条显式边界，不用把选择器越写越长。

还有一层排序：同一属性在多个 scope 里冲突时，**离根更近的胜出**。比如 `.light` 里套 `.dark` 再套 `.light`，最深那个 `.light` 的规则赢，因为它跨越的 DOM 层级最少。这正是第 03 篇最后那一步"作用域距离"——但它只在来源、重要性、层、优先级都打平后才起作用。scope 也不是沙箱：继承属性（`color`、`font-family`）仍会越过下限影响子树外部，它同样不能用 `:scope + p` 去选外面的兄弟。

### 3. `:has()`：用后代状态反向选父级

```css
.field:has(input:invalid) label { color: #a53d2b; }
```

普通选择器从右端锚点往左验证（第 02 篇）；`:has()` 把锚点换成括号内的 `input:invalid`，命中它之后再回到外面的 `.field`。括号里仍是一个相对选择器，可以继续用 `>`、`+`、`:nth-child()` 描述内部关系。**为什么它解决的是"状态驱动"？** 以前要让父级知道内部状态，得用 JS 加类名；现在选择器自己就能表达"含有无效输入的那个表单项"，DOM 不用动，JS 可以省掉。

它的优先级取括号内参数中最高的一项（和 `:is()` 同规则）。`.field:has(input:invalid) label` 是 `(0,0,2,2)`，`.field label` 是 `(0,0,1,1)`，前者更高。代价是可审查性：能用一个状态类说清时，不必为了少写一行类而把条件全塞进 `:has()`。

### 4. 三者各管一件事

| 你想解决的问题 | 用哪个 | 它不改变什么 |
| --- | --- | --- |
| 组件规则写在一起、少重复类名 | 原生嵌套 | 扁平选择器与优先级照旧 |
| 限制样式能在哪棵子树里匹配 | `@scope` | 不阻断继承，不提高优先级 |
| 根据后代状态选中外层容器 | `:has()` | 不改 DOM，不改匹配方向以外的东西 |

**为什么必须分开记？** 因为它们的失败方式不同：嵌套失败在"以为局部、其实全局命中"，scope 失败在"以为隔离、其实继承照穿"，`:has()` 失败在"以为改了结构、其实只是选中了别的元素"。把三者当成同一件事，调试时就会找错方向。

回退也要分别看：原生嵌套可交给构建链展开；`@scope` 不支持时，基础选择器仍要能独立给出可读样式；`:has()` 不支持时用 JS 补一个状态类即可，别把关键信息只挂在 `:has()` 上。

三者也可以叠着用，但要知道每层各自负责什么：用嵌套把组件规则写在一起，用 `@scope` 给这组规则画边界，用 `:has()` 表达"当内部处于某状态时，外层容器要怎么变"。叠加不会让边界更硬——继承照穿、优先级照算，只是书写和表达都更清楚了。

## 容易误判的地方

- **"嵌套让样式局部化"** → 它只是把规则写在一起，编译后仍是 `.card button` 这样的扁平选择器，照样命中所有后代。
- **"`@scope` 是样式沙箱"** → 它只限定参与匹配的子树并加邻近性排序；继承属性照穿，优先级规则照算。
- **"`:has()` 会改 DOM 或绕过优先级"** → DOM 一动不动，优先级仍取括号内参数最高的一项。

## 自己再做一次

1. 把 `.card { & button { padding: 0.5rem } }` 手工展开，用 DevTools 的 Matched Rules 核对。**预期结果**：展开为 `.card button`，特异性 `(0,0,1,1)`，与手写规则完全一致。
2. 写 `@scope (.card) to (figure) { p { color: red } }`，并在 `figure` 内放一个带自身 `font-family` 的段落。**预期结果**：figure 内的 `p` 不被这条命中（保持原色），但它从 `.card` 继承来的 `font-family` 仍生效——说明 scope 不阻断继承。
3. 写 `.field:has(input:invalid) label { color: red }` 与 `.field label { color: blue }`，切换 input 的有效性。**预期结果**：输入无效时 label 变红，恢复有效时变蓝；两条规则都不改 DOM。特异性分别是 `(0,0,2,2)` 与 `(0,0,1,1)`，红色胜出且与源码顺序无关。
